## Highlights

- **New, experimental: `shk deps`.** Audits `Cargo.lock` against the OSV crates.io advisory data, offline, with human, JSON and SARIF output.
- **Security review fixes.** A review of the whole project closed several ways a scan, a mask or a blocking AI pre-hook could pass when it should not. Many of them change behavior; read the next section before upgrading.
- **Faster scans.** `shk scan .` on a large repository is up to 13x faster, and a single AI hook call is 2–5x faster.
- **Better detection in Japanese text.** A token or PII value written directly next to kana or kanji is now found.

## Read before upgrading

### `shk doctor --strict` fails until the hooks are reinstalled

Claude Code hooks installed by v0.7.7 or earlier lack the new `PreToolUse` matchers (`Grep`, `Glob`, `WebSearch`, `Agent`, `Task`) and the new `PostToolUse` matcher (`Grep`). Without them the action guard's search-tool rules never run in Claude Code. `shk doctor` now warns about outdated pre and post matchers, so `shk doctor --strict` exits `1` with no change to your repository. `shk doctor --json` gains `claudePermissions.post_tool_matcher_ok`. ([#446](https://github.com/Kazuki-tam/security-harness-kit/pull/446), [#462](https://github.com/Kazuki-tam/security-harness-kit/pull/462))

`shk doctor` and the desktop app also stopped trusting the `_shk_managed` marker alone. A managed entry must now run `shk scan … --hook-mode <tool>` as one plain command. Hand-edited commands are reported as not installed: wrappers (`sh -c`, `env VAR=…`, `timeout 30 …`), `… || true`, `2>&1`, `--hook-mode=<tool>` with an equals sign, and configs written by shk 0.5.x whose project path contains `&`, `;` or `|`. Every command the current `install-ai` writes is still detected. ([#460](https://github.com/Kazuki-tam/security-harness-kit/pull/460))

To fix both, re-run the install and commit the result. Pass the same `--log-blocked` or `--audit` flag you used before:

```sh
shk hooks install-ai --tool claude-code
```

### Claude Code asks for permission again

A clean pre-hook scan now prints `{}` instead of `permissionDecision: "allow"`. The explicit allow skipped Claude Code's own permission prompt, so every tool call that shk did not flag was approved automatically. Claude Code now applies your permission settings to those calls again, so you may see prompts you did not see on v0.7.7. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))

### The action guard denies more commands

The guard used to key on about 35 reader command names. It now denies a dotenv argument to any shell command outside a short safe list, and reads ambiguous text every plausible way. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440), [#444](https://github.com/Kazuki-tam/security-harness-kit/pull/444), [#480](https://github.com/Kazuki-tam/security-harness-kit/pull/480))

- **Project tools that load a dotenv file themselves** are denied until you allow them under `[action_guard]` in `shk.toml`, for example `allow = ["Bash(docker compose --env-file .env up)"]`. See [Action Guard Settings](https://github.com/Kazuki-tam/security-harness-kit/blob/main/docs/configuration.md#action-guard-settings).
- **Piping into a shell** (`… | bash`, `bash < file`, `( … | bash)`) is denied as `opaque_execution`, because the script cannot be seen. A heredoc (`bash <<EOF … EOF`) is scanned and allowed when its body is clean.
- **Environment dumps followed by redirections** (`env 2>&1`, `set 2>&1`, `export -p 2>&1`, `declare -p 2>&1`) are denied as `environment_dump`.
- **Text that only looks executable** is denied more often. In a corpus of 3,275 real scripts and file bodies, 17 that v0.7.7 allowed are now denied, mostly an apostrophe inside a comment or a backtick inside an unquoted heredoc. Quoting the heredoc delimiter (`<<'EOF'`) avoids it.
- **Search tools** that name a target path count as reads, and a glob that selects a dotenv file is denied.
- **Dotenv templates are now allowed.** `.env.example`, `.env.sample`, `.env.template` and `.env.dist` can be read. Any other `.env.*` name is still denied. Claude Code's own `Read(.env.*)` deny entry, if you installed it, still refuses them in the `Read` tool. ([#442](https://github.com/Kazuki-tam/security-harness-kit/pull/442))

Known limits are listed in [Hook Action Guard](https://github.com/Kazuki-tam/security-harness-kit/blob/main/docs/detection-model.md#hook-action-guard). The guard reads the command line, so a path that never appears on it is not seen.

### Agents can no longer add their own `shk-ignore` markers

Inline markers in hook payloads and prompts are ignored. For a file that a tool call edits, a marker counts only when it is already in the file on disk. A `shk-ignore-next-line` marker counts only when the line directly below it is unchanged, so an agent cannot change a line under an existing marker or copy the marker above new text. Add such lines by hand, or use an `[[allowlist]]` entry. ([#444](https://github.com/Kazuki-tam/security-harness-kit/pull/444), [#480](https://github.com/Kazuki-tam/security-harness-kit/pull/480))

### Files outside the repository are scanned

A file outside the repository root, or behind a symlink that leaves it, is now content-scanned when a tool call only reads it. Only the first 16 MiB are read. This also applies to Cursor `beforeReadFile`. A read of such a file that holds a finding is denied. To allow dependency sources with test fixtures, add an `[[allowlist]]` entry by absolute path with a `rule_id`, for example `path = "/home/me/.cargo/registry/**"`. Findings are logged under the tool's label, so outside paths do not reach the output or `.shk/audit.log`. ([#446](https://github.com/Kazuki-tam/security-harness-kit/pull/446), [#462](https://github.com/Kazuki-tam/security-harness-kit/pull/462))

Files that start with a NUL byte, and UTF-16 files, are no longer skipped as binary. Reading a binary file can take up to about a second in the hook.

### Directory scans include more files

`.ignore` files are no longer honored, and tracked files are scanned even when a `.gitignore` rule matches them (`git add -f`). Before, a `.ignore` with `*` emptied the scan. Use `[scan].exclude` in `shk.toml` to leave paths out. ([#444](https://github.com/Kazuki-tam/security-harness-kit/pull/444))

### Policy mistakes that used to be silent

- An `[[allowlist]]` entry with none of `rule_id`, `value_hash` and `path` is a policy load error. **A policy that does not load makes every blocking AI pre-hook deny,** so check `shk.toml` with `shk scan .` after upgrading. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- Unknown allowlist keys raise a low-severity `policy.allowlist_unknown_key` finding. An `expires` value that cannot be parsed counts as expired.
- An entry that matches everything (`path = "**"` with no `rule_id` and no `value_hash`) raises `policy.allowlist_matches_everything`, and human `shk scan` output prints how many findings were suppressed. ([#458](https://github.com/Kazuki-tam/security-harness-kit/pull/458))

### `shk mask` output changes

- Input that is not UTF-8 is masked instead of passed through unchanged. The finding `mask.binary_passthrough` and the JSON placeholder `[BINARY_PASSTHROUGH]` are gone; such input yields `mask.non_utf8_input`. ([#458](https://github.com/Kazuki-tam/security-harness-kit/pull/458))
- Values that a rule matches across lines are masked, so `shk mask` can redact more than before. Line counts and line endings stay the same.
- A whole private key block is masked, from header to footer. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- With `redaction = "partial"`, a value is redacted whole when the kept characters would be more than half of it. With the default 4+4, values of 9 to 15 characters are now redacted whole. ([#460](https://github.com/Kazuki-tam/security-harness-kit/pull/460))

### More findings in Japanese text

<!-- shk-ignore-next-line pii.ipv6 -->
A token or PII value written directly next to kana, kanji or full-width characters is now matched, by the gitleaks rules and by shk's own rules. Before, such a value was missed, and its raw text could appear in JSON `context_before` / `context_after`. Expect new findings in Japanese documents, including Low and Info ones: `pii.ipv6` also flags `12:34:56に`-style times, and `pii.en.phone` flags 3-3-4 digit groups that touch kana. Value hashes change for tokens that end in `-` or `=` directly before Japanese text. ([#463](https://github.com/Kazuki-tam/security-harness-kit/pull/463), [#464](https://github.com/Kazuki-tam/security-harness-kit/pull/464))

### npm package layout

The `security-harness-kit` npm package no longer downloads the binary in a `postinstall` script. It now has no dependencies and no install scripts, and takes the binary from a platform package (`security-harness-kit-<os>-<cpu>`) listed as an optional dependency. ([#441](https://github.com/Kazuki-tam/security-harness-kit/pull/441))

- The launcher needs **Node.js 18 or later**.
- Do not install with `--omit=optional` or `--no-optional`, and do not copy `node_modules` between operating systems or CPUs. Without the platform package, `shk` prints the reason and exits `2`.
- The install now works with `ignore-scripts=true`, behind an npm mirror, and without access to `github.com`.

### Other changes

- **Pre-commit hook:** the managed block exits with the scan's status, so a failing scan blocks the commit even when other commands follow. With `core.hooksPath` pointing outside the repository, `shk hooks install` fails with instructions and `shk init` warns and continues. With husky v9, `shk doctor` now finds the scan line in `.husky/pre-commit`. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440), [#480](https://github.com/Kazuki-tam/security-harness-kit/pull/480))
- **`shk env encrypt`** rejects lines that are not assignments instead of copying them through in plaintext. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- **`shk env key migrate`** now moves the pseudonymize key with the env keys. A project migrated by v0.7.7 or earlier that has since run pseudonymize has a different key in each backend, and migrating again stops with a conflict. [`shk env key migrate`](https://github.com/Kazuki-tam/security-harness-kit/blob/main/docs/commands.md#shk-env-key-migrate) describes how to resolve it. ([#460](https://github.com/Kazuki-tam/security-harness-kit/pull/460))
- **`shk scan --git-history`** on a repository whose history has a path with a line break needs Git 2.38 or later. Older Git fails with a message that says so. ([#458](https://github.com/Kazuki-tam/security-harness-kit/pull/458))
- **Pseudonymize** refuses more xlsx and CSV/TSV inputs that would leak a selected value into another place: pivot caches, cached formula or chart values, and rows swallowed by an unbalanced quote. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440), [#480](https://github.com/Kazuki-tam/security-harness-kit/pull/480))

## New: `shk deps` (experimental)

`shk deps audit` checks the packages pinned in `Cargo.lock` against known vulnerabilities, malicious-package reports and RustSec informational advisories. `shk deps update` downloads the public [OSV](https://osv.dev) crates.io dump and builds a local index. The audit itself runs offline, so nothing about your dependencies is sent anywhere. ([#481](https://github.com/Kazuki-tam/security-harness-kit/pull/481)–[#489](https://github.com/Kazuki-tam/security-harness-kit/pull/489))

```sh
shk deps update
shk deps audit
shk deps audit --update --sarif > deps.sarif
```

- Rules: `deps.malicious`, `deps.vulnerable` (severity from CVSS), `deps.unsound`, `deps.unmaintained`, `deps.notice`, `deps.source_unreadable` and `deps.data_stale`.
- Exit codes: `0` below the threshold (also when there is no `Cargo.lock`), `1` at or above it, `2` when the audit cannot run.
- Settings: `[thresholds].deps_fail_on`, `[deps].stale_after_hours` and `[[deps.ignore]]` exceptions with an `expires` date. An invalid `[deps]` section affects only `shk deps`; `shk scan` and the AI hooks ignore it.
- The index is not signed. Whoever can write the cache directory (`SHK_DEPS_CACHE_DIR`) decides what the audit sees, so share it only between jobs you trust.

Only Cargo is supported, and rule ids, setting names and output may still change. See [`shk deps`](https://github.com/Kazuki-tam/security-harness-kit/blob/main/docs/commands.md#shk-deps) and [Dependency Audit Settings](https://github.com/Kazuki-tam/security-harness-kit/blob/main/docs/configuration.md#dependency-audit-settings).

## Fixed

- `shk scan --staged` read the wrong blob for a file whose name starts with `<digit>:`. Staged content is now read by object id. ([#444](https://github.com/Kazuki-tam/security-harness-kit/pull/444))
- A crafted repository could run a command through `git ls-files` during a directory scan. That call now runs with protocols, lazy fetch and fsmonitor disabled. ([#444](https://github.com/Kazuki-tam/security-harness-kit/pull/444))
- User prompts whose `prompt` is a list, an object, or blank with the text under another key were allowed unscanned. ([#446](https://github.com/Kazuki-tam/security-harness-kit/pull/446), [#462](https://github.com/Kazuki-tam/security-harness-kit/pull/462))
- Claude Code `PostToolUse` now scans short plain-string and `filenames` results. ([#462](https://github.com/Kazuki-tam/security-harness-kit/pull/462))
- Blocking pre-hooks fail closed on internal errors (empty or invalid input, unreadable file, scan failure) with a short reason that holds no path. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- `shk scan --git-history` lost findings after a committed path with a line break. ([#458](https://github.com/Kazuki-tam/security-harness-kit/pull/458))
- UTF-16 files with a byte order mark are decoded and scanned, and a UTF-8 byte order mark no longer hides the first line. A document whose text cannot be extracted is scanned as raw bytes. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- JSON `context_before` / `context_after` no longer show private key lines or lines inside a multi-line match. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- `shk audit` replaces control, bidi and invisible formatting characters taken from the log, which may come from a cloned repository. ([#446](https://github.com/Kazuki-tam/security-harness-kit/pull/446), [#462](https://github.com/Kazuki-tam/security-harness-kit/pull/462))
- `shk mcp audit` sees MCP servers started through `cmd /c`, `env`, `.cmd`/`.exe`, `bunx`, `pnpm dlx`, `yarn dlx` and `npm exec`. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- `shk doctor workflows --fix` no longer corrupts a flow-style `with:` mapping; it reports it for a manual fix. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- `shk init` can be re-run without `--force`, and removing hooks keeps safety settings you added yourself. ([#440](https://github.com/Kazuki-tam/security-harness-kit/pull/440))
- Dependency updates fix the open RustSec advisories. ([#479](https://github.com/Kazuki-tam/security-harness-kit/pull/479))

## Performance

The generated gitleaks rules use ASCII word classes, and keywords are found in one pass. `shk scan .` on this repository dropped from 2.1 s to 0.16 s, and a single-file hook scan is 2–5x faster. ([#463](https://github.com/Kazuki-tam/security-harness-kit/pull/463))
